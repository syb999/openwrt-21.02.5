dss 命令示例

当前配置：A / B 默认都是 DeepSeek（网页，需令牌）。GLM-4-Flash 作为备用：加 --backend-a api。
注意：命令台只执行以 dss 开头的命令；其它内容一律当作一句话提问传给 dss（dss "…"），不会执行任何外部命令。 所有命令在路由器的 shell 里执行（SSH 或 ttyd）。命令行参数永远优先于设置页。
基础
dss
提示符是 [shell]>，输入 exit 退出。
dss "用一句话解释什么是 SLIC 接口"
printf "1+1=?\n中国的首都是哪里？\n" | dss
这条请在 SSH 里执行（命令台只接受 dss 命令）。
后端：DeepSeek 与 GLM-4-Flash
dss "问题" --backend-a api
免费、首字约 0.7 秒。glm-4.5-flash 慢很多（约 8 秒），不要用。
dss "问题" --backend-a deepseek
令牌失效（40003）时打开下一节的令牌页面刷新；被禁言期间不要用。
http://10.80.1.112:88/token
登录 chat.deepseek.com 后点一下书签，token 会自动写入。GLM 不需要这一步。
附件（仅 DeepSeek 支持）
dss --file /root/AR9341.PDF "这份文档里 SLIC 的 DMA 描述符怎么定义？"
dss --file /root/AR9341.PDF --file /root/SI3217XB.PDF "对比两边的 SPI 时序"
每个会话只上传一次。GLM-4-Flash 是纯文本接口，不接受附件。
dss --code --duet --pause 3 --pace 8 --file-b /root/AR9341.PDF --file-b /root/SI3217XB.PDF "使用 ar9341 通过 slic 接口对接 si3217x 实现 voip 全代码"
--file 给两侧，--file-a / --file-b 只给指定侧。
dss --duet --file-a /root/AR9341.PDF "问题"
代码模式
dss --code "用 C 写一个读取 /proc/meminfo 打印 MemAvailable 的完整程序"
代码模式要求输出完整文件，逐个存到 /root/.dss/out，可用 !run N 执行。
dss --code --file /root/AR9341.PDF --file /root/SI3217XB.PDF "使用 ar9341 通过 slic 接口对接 si3217x 实现 voip 全代码"
抓取网页 / JS 分析（--url / --url-dom）
dss --url https://example.com/static/app.js --role jsrev "分析这个文件的接口、签名参数和反调试手段"
--url 用 curl 抓原始内容（静态 HTML / .js / .json 最快），抓下来的文件当附件上传给模型。
dss --url-dom https://example.com/login --role selenium "给出点击『登录』按钮并输入用户名的 Python Selenium 代码，用显式等待"
--url-dom 用 chrome-headless-shell 渲染后再导 DOM（SPA、JS 生成的元素必须用这个），首次约 30 秒。拿到的 DOM 里能直接看到真实的选择器/类名。
dss --url-dom https://example.com/login --url https://example.com/static/app.js --role jsrev,selenium "结合页面 DOM 和这个 JS，说明登录接口的参数怎么算，并给出 Selenium 自动化脚本"
都能重复写。注意：模型本身不能联网，只能分析抓下来的内容；附件只支持 DeepSeek 后端（GLM-4-Flash 是纯文本接口）。
环境缺失时会自动跳过并提示补全命令：--url 需要 curl（opkg install curl）、--url-dom 需要 chrome（opkg install chrome-glibc-runtime chrome-headless-shell）、--autorun 需要 python3（opkg install python3）。
对话角色
dss --role ppt "做一份 AR9341 VoIP 方案 PPT 的大纲"
可用角色：embedded / android / cdev / novelist / arch / reviewer / tester / doc / voip / net / security / teacher / gamedev / webdev / routerdev / devops / dataeng / ai / translator / pm / ppt / shortvideo / jsrev / selenium（也可直接写自定义中文角色名）。
dss --duet --rounds 3 --role-a arch --role-b reviewer "评审这套 VoIP 方案"
不写 --role/--role-a/--role-b 时，自动用设置页里勾选的角色（单发用 A 侧）；写了就完全以命令行为准。
自动运行产物（--autorun）
dss --code --autorun "做一份 5 页的 AR9341 VoIP 方案 PPT，保存为 voip.pptx"
--autorun（别名 --run）会在代码存盘后立刻在路由器上执行 .py / .sh，并打印这一轮新增的产物路径，例如 [dss] 产物: /root/.dss/out/voip.pptx；随后到「代码文件」页下载即可。
dss --code "用 python-pptx 生成 3 页 PPT，保存为 demo.pptx"
不加 --autorun 时只保存脚本到 /root/.dss/out，可用 !run N 在会话里手动执行。
dss --code --autorun "生成 PPT 并保存为 out.pptx"
脚本跑挂时，dss 把完整 traceback 发回模型，要求它重写完整脚本（不是打补丁）并重跑，最多 2 次。环境是 OpenWrt + python3.9，已装 python-pptx / lxml / Pillow。
dss --code --autorun --duet --rounds 2 "写两个独立的 python 脚本：a 生成 PPT，b 生成 CSV"
duet 时两侧文件自动加前缀：A 侧 a_*.py、B 侧 b_*.py，不会因为同名被追加合并成坏文件。
自问自答（duet）
dss --duet --rounds 3 "用三句话说明TCP三次握手，然后指出一次常见误解"
dss --duet --rounds 5 --pause 3 --pace 8 --backend-a api --backend-b api --model-a glm-4-flash --model-b glm-4-flash "对比 RST 与 FIN 的差别并给出抓包判据"
dss --pace 8 --pause 3 "问题"
duet 两侧必须同一后端：deepseek+deepseek 或 api+api。实测混跑（deepseek+glm）会让网页版被判异常、DeepSeek 直接被踢下线要求重登。
--pace 是两次请求间隔秒数（默认 5），--pause 是每轮 duet 前等待秒数（默认 2）。被限流时自动按 5/10/30 分钟退避。
会话内斜杠命令
!list            列出这条回答里保存的代码文件
!cat 1           查看第 1 个文件
!run 1           执行（.sh / .py / .c，C 会先 gcc 编译）
!run 1 send      执行并把输出/编译错误发回给模型继续修
!out 1           把上次执行输出发回对话
!upload /root/AR9341.PDF    上传并附加到后续问题
!files                      列出已附加文件
!refile                     下次提问重新发送附件
!detach                     清空附件
!search on|off     联网搜索开关
!help              帮助
exit               退出
常见错误
http://10.80.1.112:88/token
DeepSeek 网页令牌过期，去令牌页刷新。与 GLM 的 API Key 无关。
dss --duet --file-b /root/AR9341.PDF "问题"
GLM-4-Flash 是纯文本接口，用 --file-b 把文件给 DeepSeek 那一侧。
文件位置
/root/.dss/cred              DeepSeek 网页令牌（0600）
/root/.dss/openai.cred       API 后端 base / key / model（0600）
/root/.dss/out               保存下来的代码（持久）
/tmp/dss_output              本次会话的脚本
/tmp/dss/conversation.log    对话日志
