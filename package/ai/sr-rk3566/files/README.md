# 超分（2 倍画面优化，RK3566 NPU）

`sr-rk3566.py <输入> <输出> [进度文件]`

脚本自己探分辨率，按“模型优先、块数最少”挑模型（列表顺序就是优先级）：

| 片源 | 模型 | 模型输入 | 切块 | 输出 |
|---|---|---|---|---|
| 576×432（4:3 SD） | `av3_576x432.rknn` | 576×432 | 1 块（无接缝） | 1152×864 |
| 640×480 及更小（4:3） | `av3_640x480.rknn` | 640×480 | 1 块 | 源 ×2 |
| 640×360（16:9 SD） | `av3_640x360.rknn` | 640×360 | 1 块 | 1280×720 |
| 比大模型还大 | `av3_res.rknn` / `av3_320x180.rknn` | 288×216 / 320×180 | 多块，丢 32px 边 | 源 ×2 |

源片 ≤ 模型尺寸时整帧一块，**没有块边界，也没有接缝**；只有源片比模型大时才切块，
每块只保留中心区域（块边缘 32px 因 zero-padding 是坏的，由相邻块补）。

## 实测

```
576x432 源 + av3_576x432（1 块）：5.15 秒/帧（25 帧 139 秒）
640x360 源 + av3_640x360（1 块）：约 5 秒/帧
编码走 h264_rkmpp，音频从原片 copy；-aspect 必须写，否则 SAR 为空、播放器按 16:9 拉伸
```

## 插件怎么调

`video` 插件的 `op=sr` 会拼成：

```sh
python3 /opt/sr-rk3566/sr-rk3566.py <源.mp4> <输出.mp4> /tmp/agent-jobs/<id>.prog
```

第 3 个参数是进度文件，格式跟 ffmpeg `-progress` 一样（`out_time_us=` /
`progress=end`），插件的 `op=job` 直接读它换算百分比。解码、逐帧推理、编码
三个阶段都会更新，页面上的进度条才不是死的。

## 文件

```
sr-rk3566.py        主脚本（选模型 / 切块 / 推理 / 编码）
anime4k_rknn        aarch64 推理器（18KB C，静态，跑 /opt/glibc 的动态库）
av3_576x432.rknn    576x432 输入（4:3 首选）
av3_640x480.rknn    640x480 输入
av3_640x360.rknn    640x360 输入（16:9）
av3_res.rknn        288x216 输入（小块兜底）
av3_320x180.rknn    320x180 输入（小块兜底）
```

## 已知限制

- **源片太糊时效果有限**：模型只在已有结构上收紧边缘，不会凭空生成细节。
- **模型输入尺寸编译期固定**：RKNN 在 RK3566 上不支持 dynamic_input，换尺寸要重新转。
- **转换很慢**：这台机器没 AVX，rknn-toolkit2 要跑在 qemu 里，约 0.65 分钟/GFLOP。
- **720p 以上直接拒绝**：那已经不叫 SD 源，跑超分只会更慢更难看了。

## 踩过的坑

1. **权重是残差式** —— 输出要加上输入的最近邻放大，否则一片黑（均值 0.009）
2. **fp16 RKNN 不套 mean/std** —— `1/255` 必须写进 ONNX 图
3. **写进图的 1/255 会被折进卷积** —— 残差分支要单独走一条 1×1 卷积 + DepthToSpace
4. **ONNX 的 Resize 会让 rknn-toolkit2 的 fold_constant 死循环** —— 用 DepthToSpace 代替
5. **输出必须写 `-aspect`** —— 否则 SAR=N/A，盒子按 16:9 拉伸
6. **不要缩小画面** —— 切块是原生裁剪，缩放会永久丢细节
7. **块边界 32px 是坏的** —— 模型在块边缘做 zero-padding，感受野被截断
